# Bundled bubblewrap

This crate carries bubblewrap 0.13.1 and libcap 2.78 in RODE's native helper.
Cargo builds both from the checked-in C sources. There is no runtime download,
separate executable cache, system-package installation, setuid bit, or dependency
on Codex. System `bwrap` remains the first choice; a failed system probe is not
retried with this implementation. Namespace/AppArmor restrictions still apply.

The helper's `--bwrap-launch` flag invokes the upstream process entry point
before GUI initialization or service threads. It must run in a fresh process:
bubblewrap owns descriptor cleanup, namespace setup, exec, and process exit.
The launch flag and read-only helper mount are included in the captured policy.
Only implementation-specific helper paths are normalized for reattachment.

Builds need a C compiler and Linux UAPI headers. Static musl builds also need a
target C toolchain (`musl-tools` for native Debian/Ubuntu builds). libcap is built
statically from its vendored sources; no host `libcap-dev` or runtime library is
required. Cross builds must supply a target compiler/sysroot through Cargo/cc's
standard `CC_<target>` and `CFLAGS_<target>` settings.
Native musl builds discover missing Linux UAPI include roots from the native
compiler. Cross builds never borrow headers from the build host.

## Source provenance and updates

`vendor.json` records the upstream release URLs, archive SHA-256 values and
checksums of the included files. The C sources and headers are unmodified.
Bubblewrap's generated `config.h` sets its version string; no SELinux integration
or weaker kernel assumptions are enabled. libcap's `cap_names.h` and
`cap_names.list.h` are generated by its upstream Makefile from the included
capability header, with `USE_GPERF=no`. They are target independent.

To update, verify the upstream releases, replace the listed sources and licenses,
regenerate the capability-name headers using upstream's build rules, and refresh
`vendor.json` and `LICENSES/NOTICE.txt`. Update the version string in `build.rs`
and the launcher regression. Test both native and static musl entry points,
missing-PATH preparation, system-program precedence, enforced isolation in CI,
SSH without system bubblewrap, and helper-relocation fingerprints.
